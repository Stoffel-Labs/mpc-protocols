# Masked-Open Lemma & $\mathcal{F}_{\mathsf{TruncPr}}$


The core proof artifact for upgrading the statistical-layer operations (TruncPr first; Mod2 and KOrCL by re-parameterization) to composable security. Companion to the HBMPC Security Assumption Audit and the PRandInt/RISS Security Proof.

## 1. Setting, model, and notation

**Adversary and network.** Static active adversary corrupting a set $C$ of at most $t$ parties, $t < n/3$, $n$ parties total. Security with abort; asynchronous message delivery (liveness argued separately, per the review's standing convention). Statistical security parameter $\kappa$; on the PRSS path, additionally a PRF assumption.

**Hybrid model.** The protocol is analyzed in a hybrid world with ideal access to:

- **$\mathcal{F}_{\mathsf{ABB}}$** — the arithmetic black box. Holds every shared value under a *handle*; parties invoke operations by handle. Crucially, an operation's input values are $\mathcal{F}_{\mathsf{ABB}}$ state *before* the operation's first message exists. Linear operations on handles are local and free.
- **$\mathcal{F}_{\mathsf{PRandM}}(m, w)$** — the mask supplier. Creates handles to: `r′`, uniform on `[0..2^m)`, composed from $m$ uniform bits (each bit also available as a handle); and `r″`, distributed as the sum of $C(n,t)$ contributions, each uniform on `[0..2^w)` — one contribution per maximal unqualified set $T$. The adversary knows the contributions of every set $T$ that excludes at least one corrupted party; exactly one contribution (the set $T^{*} = C$) is unknown to it. On the PRSS path the $T^{*}$ contribution is a PRF output under a key the adversary does not hold; on the RISS path it is a true uniform sample.
- **Open** — ideal public reconstruction: reveals the value under a handle to all parties and the adversary.

**Notation.** Values with bars ($\bar{a}$) are signed integers in $\mathbb{Z}_{\langle k \rangle} = [-2^{k-1}+1 .. 2^{k-1}-1]$, encoded in $\mathbb{Z}_q$ as $a = \bar{a} \bmod q$. $\nu = \lceil \log_2 C(n,t) \rceil$. The pool width satisfies the per-operation check $w \ge (\ell - m) + \kappa$ where $\ell$ is the bit-width of the value being masked (in code: `mask_bits − value_bits ≥ κ`, $\kappa \ge 44$).

**Real-to-hybrid correspondence** (justified in §5d, not assumed): handles = consistent degree-$t$ Shamir sharings held by $\ge 2t+1$ honest parties; Open = share broadcast + Tier-1 robust Reed–Solomon reconstruction; $\mathcal{F}_{\mathsf{PRandM}}$ = the RandBit pool and the PRandInt pool (PRSS-derived or RISS-generated, the latter's active security given by the PRandInt/RISS Security Proof).

## 2. The coupling finding

**Claim.** No protocol with TruncPr's communication pattern can UC-realize a functionality that reveals nothing to the adversary. The realizable functionality must leak the opened value.

*Assumptions of the claim:* at least one corruption, and a target $F$ that is both leak-free *and influence-free* on $u$. Influence-freeness cannot be dropped: even an $F$ that accepts an adversarially chosen $r'$ fails, because consistency requires $c \bmod 2^m \equiv \bar{a} + r'$, which is uncomputable without $\bar{a}$.

**Why.** Write $b = 2^{k-1} + \bar{a}$, $b' = b \bmod 2^m = \bar{a} \bmod 2^m$, and let $c$ be the opened value, $c' = c \bmod 2^m$. By the protocol's own correctness analysis (FC2010, Protocol 3.1), the carry bit in the output $d = \lfloor \bar{a}/2^m \rfloor + u$ satisfies

$$
u = \mathbf{1}[\,c' < b'\,]
$$

— a deterministic function of the public $c$ and the input $\bar{a}$. Now consider a UC environment $Z$: it supplied $\bar{a}$ (so it knows $b'$), it observes $c$ through any corrupted party, and it can later open $d$ through the ideal interface and recover $u = d - \lfloor \bar{a}/2^m \rfloor$. In every real execution, the pair $(c, u)$ is consistent with the equation above. In an ideal world whose functionality leaks nothing, the simulator must fabricate $c$ with no knowledge of $\bar{a}$ while the functionality samples $u$ on its own — the two are independent, so $Z$'s consistency check $u =? 1[c' < b']$ fails with constant probability (for independent Bernoulli($p$) variables the agreement probability is $p^2 + (1-p)^2 < 1$ whenever $0 < p < 1$). Constant-advantage distinguisher; the leak-free functionality is unrealizable. ∎

**What this does and does not mean.**

- It is *not* an attack and *not* additional information leakage: the marginal of $c$ moves by at most $2^{-\kappa_{\mathrm{eff}}}$ across inputs (§5c), so nothing new is learned about $\bar{a}$. The coupling is between two things the environment already holds.
- It *is* a constraint on the security claim that is true of this protocol: "reveals a value statistically independent of the input, with the output's rounding direction consistent with that value" — not "reveals nothing."
- It is invisible at the source paper's standard (semi-honest view simulation: corrupted parties' outputs are shares of $d$, never $d$ itself) and appears exactly at the composable standard, where the environment closes the loop between inputs, leakage, and later-opened outputs.
- Consequence for the proof architecture: define $\mathcal{F}_{\mathsf{TruncPr}}$ to sample the mask itself, leak $c$, and derive $u$ from the same randomness (§3). The simulation then becomes perfect (§5b), and all statistical content is concentrated in one property of $F$'s leakage (§5c).

## 3. Definition: $\mathcal{F}_{\mathsf{TruncPr}}$ (leaky formulation)

Parameters: $k, m$ with $0 < m < k$; pool parameters $(w, \kappa, \nu)$ from §1. A command on the extended ABB.

On input `(truncpr, id_a, id_d)` from the honest parties, with $\bar{a} \in \mathbb{Z}_{\langle k \rangle}$ stored under `id_a`:

1. Sample $r'$ uniform on `[0..2^m)`, and $r''$ from the pool distribution (sum of $C(n,t)$ contributions, each uniform on `[0..2^w)`; corrupted-set contributions taken from the adversary's registered values — see §5c).
2. Compute, over the integers, `c = 2^{k−1} + ā + 2^m·r″ + r′`. (The parameter regime of §5a excludes wraparound mod $q$.)
3. **Leak $c$ to the adversary**, and deliver $c$ to all parties as the opened value.
4. Set `u = ⌊((ā mod 2^m) + r′)/2^m⌋ ∈ {0,1}` and store `d = ⌊ā/2^m⌋ + u` under `id_d`.

**Properties carried with the definition:**

- *Output distribution (paper-exact):* $d = \lfloor \bar{a}/2^m \rfloor + u$ with $\Pr[u=1] = (\bar{a} \bmod 2^m)/2^m$ — probabilistic rounding toward the nearest integer, exactly as FC2010's correctness analysis states for Protocol 3.1, because $r'$ is exactly uniform on $[0, 2^m)$.
- *Internal consistency:* $u$ is derived from the same $r'$ that enters $c$, so the $(c, d)$ joint matches the real protocol by construction — this is what dissolves the §2 obstruction.
- *Leakage quality:* the marginal distribution of the leaked $c$ shifts by at most $2^{-\kappa_{\mathrm{eff}}}$ across any two inputs (Lemma, part c), where $\kappa_{\mathrm{eff}} = w - (k - m) \ge \kappa$; plus $\mathrm{Adv}_{\mathrm{PRF}}$ on the PRSS path.

**Remark (why $F$ leaks all of $c$).** Only the **low $m$ bits of $c$** must be leaked; the high word is simulatable from the $\kappa$-slack, so the minimal realizable functionality leaks $c \bmod 2^m$. $F$ leaks all of $c$ to match the protocol, and the extra component is exactly the simulatable part, so nothing is lost. Leaking only $u$ does *not* suffice: conditioned on $u = 1$, the real $c \bmod 2^m$ is uniform on an interval the simulator doesn't know.

**Instantiations for the other two red cores (full, with verified output laws).** Both are strictly easier cases than TruncPr: their outputs are *deterministic* functions of the input (exact parity, exact OR), so the §2 coupling obstruction does not arise. Each therefore admits two valid formulations — the leaky one below (perfect simulation on the RISS path, uniform with TruncPr's budget interface), or a clean leak-free functionality with statistical simulation error $\le 2^{-\kappa_{\mathrm{eff}}}$ per call (with no output coupling, a simulator sampling $c$ from the reference distribution cannot be contradicted). The leaky formulation is adopted for all three so §6's accounting stays uniform; the leak-free option is recorded for callers that may need it. The PRSS caveat (computational, single global hybrid) applies identically.

- **$\mathcal{F}_{\mathsf{Mod2}}$** — parameters $(\ell, m) = (k, 1)$. On `(mod2, id_a, id_out)`: sample $r_0'$ uniform bit and $r''$ from the pool; compute $c = 2^{k-1} + \bar{a} + 2r'' + r_0'$ over $\mathbb{Z}$; **leak $c$**; store $a_0 = \bar{a} \bmod 2$ under `id_out`. *Output law (verified):* $c \bmod 2 = (\bar{a} + r_0') \bmod 2$ since every other term is even (requires $k \ge 2$ and $m = 1 \le k-1$), so the protocol's local step $[a_0] = c_0 + [r_0'] - 2c_0[r_0']$ — linear given public $c_0$ — recovers exactly $\bar{a} \bmod 2$. Masked-Open Lemma applies verbatim at $(k, 1)$.
- **$\mathcal{F}_{\mathsf{KOrCL}}$** — parameters $\ell = m' = \lfloor \log_2 k \rfloor + 1$. On `(korcl, id_{a_1..a_k}, id_out)` with each $a_i$ a shared bit: sample $r'$ uniform on $[0, 2^{m'})$ bit-composed and $r''$ from the pool; compute $c = \sum a_i + r' + 2^{m'}r''$ over $\mathbb{Z}$; **leak $c$**; store $\mathrm{OR}(a_1..a_k)$ under `id_out`. *Output law (verified — the sum-$\le$-$k$ argument):* let $s = \sum a_i \le k < 2^{m'}$ and $c' = c \bmod 2^{m'} = s + r' - u \cdot 2^{m'}$, $u \in \{0,1\}$. The protocol forms $d_i = c'_i \oplus r'_i$ (linear in $[r'_i]$ given public $c'$) and feeds $d$ into KOrCS (perfect core). Then $\mathrm{OR}(d) = [s \ge 1]$ for **both** carry values: $s = 0 \Rightarrow c' = r' \Rightarrow d = 0$; $s \ge 1, u = 0 \Rightarrow c' = s + r' > r' \Rightarrow d \ne 0$; $s \ge 1, u = 1 \Rightarrow c' = r'$ would force $s = 2^{m'}$, impossible since $s \le k < 2^{m'}$. The strict inequality $k < 2^{m'}$ is load-bearing — it is exactly what makes the carry harmless. Masked-Open Lemma applies at $(m', m')$ with the pool's width check giving $\kappa_{\mathrm{eff}} \ge \kappa$ trivially (the masked value is only $m' \approx \log k$ bits wide).

## 4. The Masked-Open Lemma: statement

**Protocol $\Pi_{\mathsf{MO}}$ (hybrid).** Parties hold a handle to $\bar{x} \in [0..2^\ell)$ in $\mathcal{F}_{\mathsf{ABB}}$ and mask handles from $\mathcal{F}_{\mathsf{PRandM}}(m, w)$. They compute, by local linear operations on handles,

$$
c \;=\; \text{const} + \bar{x} + 2^{m} r'' + r'
$$

and invoke Open on the result. (For TruncPr: const = $2^{k-1}$, $\ell = k$. For Mod2: $m = 1$. For KOrCL: $\ell = \lceil\log_2 k\rceil+1$.)

**Lemma.** In the ($\mathcal{F}_{\mathsf{ABB}}$, $\mathcal{F}_{\mathsf{PRandM}}$, Open)-hybrid model, against a static active adversary corrupting at most $t < n/3$ parties:

**(a) Correctness (no-wrap).** If $q > 2^{\ell+\kappa+\nu+1}$ and every corrupted contribution to $r''$ passes the range check ($< 2^w$), then the opened value equals the integer sum $c = \text{const} + \bar{x} + 2^m r'' + r'$, with no reduction modulo $q$.

**(b) Perfect simulation — RISS path; computational on PRSS.** $\Pi_{\mathsf{MO}}$ realizes the leaky functionality with **zero** simulation error when the $T^{*}$ contribution is a true uniform sample (RISS path). On the PRSS path, perfectness is *false* against unbounded distinguishers — the real $T^{*}$ contributions across calls are correlated outputs of one PRF key while $\mathcal{F}$ samples fresh uniforms — and the realization is computational, via a single global hybrid replacing the $T^{*}$ keystream with a random function (accounting in §6). The simulator is straight-line and black-box in both cases.

**(c) Leakage privacy.** For any two inputs $\bar{x}_0, \bar{x}_1 \in [0..2^\ell)$, the leaked value's distributions satisfy

$$
\Delta\big(c(\bar{x}_0),\; c(\bar{x}_1)\big) \;\le\; 2\cdot 2^{-\kappa_{\mathrm{eff}}},\qquad \kappa_{\mathrm{eff}} = w - (\ell - m)
$$

even conditioned on everything the active adversary knows (its PRSS keys for all sets but one, its own chosen RISS contributions, its $t$ shares of every handle). On the PRSS path the bound gains an additive $\mathrm{Adv}_{\mathrm{PRF}}$ term.

**(d) Composable form.** The simulator of (b) operates forward-only against an interactive environment; combined with the hybrid modeling (inputs are $\mathcal{F}_{\mathsf{ABB}}$ state before the first message), the realization is UC, not merely stand-alone. The real-to-hybrid step — that share-based execution with robust reconstruction implements this hybrid — is argued separately in §5d.

## 5. Proof

**Formal statement (model, tagging, and the exact claim).** Everything below proves the following theorem. *Model:* $n = 3t+1$ parties; static active adversary corrupting a fixed set $C$, $|C| \le t$, chosen before execution; asynchronous network with adversarial message scheduling and eventual delivery; secure point-to-point channels; the ($\mathcal{F}_{\mathsf{ABB}}$, $\mathcal{F}_{\mathsf{PRandM}}$, $\mathcal{F}_{\mathsf{Open}}$)-hybrid model of §1, with $\mathcal{F}_{\mathsf{Open}}$'s asynchronous interface as fixed in §6B and $\mathcal{F}_{\mathsf{PRandM}}$ carrying the PRSS interface explicitly: it hands the adversary every per-set contribution computable from $C$'s keys and samples the one unknown contribution $f_{T^{*}}$ truly uniform at each fresh address — so §5 contains no PRF anywhere, and the computational cost of realizing $\mathcal{F}_{\mathsf{PRandM}}$ by the actual keystream is charged once, in §6 Step 1, never here. *Instance tagging:* throughout, an *instance* (synonymously, an *invocation*) is one masked-open call of $\Pi_{\mathsf{MO}}$ — one $\mathcal{F}_{\mathsf{TruncPr}}$/$\mathcal{F}_{\mathsf{Mod2}}$/$\mathcal{F}_{\mathsf{KOrCL}}$ execution; this is finer than §6C's unit (one top-level operation = one `SessionId`) and unrelated to §6C's `instance_id`, which names a whole deployment execution (§6C condition C). An instance is identified by its enclosing operation's `SessionId` `sid = (calling_protocol, instance_id, exec_id, sub_id, round_id)` together with its assigned batch slice `[p_lo..p_hi)`; its mask randomness is that slice of the keystream addressed by `sid`, and no two instances' address sets intersect — §6C MI-1 (disjoint within-operation prefixes; injectivity across operations and types) and MI-3 (cross-node agreement), under §6C's conditions A–C — which is what makes the instances disjoint sub-modules despite the single PRSS key object. *Claim:* each $\Pi_{\mathsf{MO}}$ instance UC-realizes its leaky functionality $\mathcal{F}$ of the §3 family — an extension of $\mathcal{F}_{\mathsf{ABB}}$ by one leaky command, taking ABB handles as input and storing its result under an ABB handle — with **zero** simulation error: for every static active adversary A there is the straight-line black-box simulator S of (b) such that for every environment Z the real and ideal executions are identically distributed, where Z may choose the instance's input adaptively from all prior public outputs *and* is additionally given direct access to the shared hybrid functionalities — it may issue arbitrary further $\mathcal{F}_{\mathsf{ABB}}$ and $\mathcal{F}_{\mathsf{Open}}$ commands, and $\mathcal{F}_{\mathsf{PRandM}}$ queries at addresses outside this instance's slice, concurrently with the instance (the statement is with respect to the extended ABB as an exposed shared subroutine, in the sense of UC with global subroutines; completeness of the dummy adversary collapses the quantifier over A). This exposed form is exactly what §6's per-invocation replacement consumes. Parts (a)–(d) are the proof: (a) exactness of the output law, (b) the zero-error simulator, (c) input-independence of the declared leak up to $2^{-\kappa_{\mathrm{eff}}}$, (d) the composable form — input committed before the instance's first action (no delayed-input channel) and the real-to-hybrid justification.

### (a) Correctness — no wraparound

Bound each term: $\text{const} + \bar{x} < 2^\ell$ (after the signed-to-unsigned shift), $r' < 2^m$, and $r'' < C(n,t)\cdot 2^w$ so $2^m r'' < 2^{m+w+\nu}$. With the pool regime $w = (\ell - m) + \kappa$ this gives $c < 2^{\ell+\kappa+\nu+1} < q$, so the $\mathbb{Z}_q$ computation coincides with integer arithmetic. Two active-adversary preconditions, both discharged by existing code: (i) corrupted contributions to $r''$ must actually lie in $[0..2^w)$ — enforced by the strict range check that rejects any opened RISS contribution at or above the declared bound; (ii) the per-operation width check `mask_bits − value_bits ≥ κ` must pass, else the operation refuses to run. A corrupted contribution cannot overflow the bound by construction on the PRSS path (contributions are PRF outputs reduced into $[0..2^w)$).

### (b) Perfect simulation

In the hybrid world the adversary's entire view of $\Pi_{\mathsf{MO}}$ is: its own interface to $\mathcal{F}_{\mathsf{ABB}}$ and $\mathcal{F}_{\mathsf{PRandM}}$ (its $t$ shares / its registered contributions — identical in real and ideal by definition of those functionalities), and the single value $c$ produced by Open. The simulator S receives exactly $c$ from the leaky functionality's leak and forwards it as the Open result. Every bit of the view is therefore *equal*, not merely close, between the two worlds; the output stored under the result handle is derived from the same $(r', r'')$ in both worlds by construction of $\mathcal{F}$. Simulation error: 0. S never rewinds, never looks ahead, and uses only oracle access to the adversary — straight-line black-box. ∎

The force of this step is architectural: *all* statistical and computational cost has been moved out of the simulation and into the next part, as a measurable property of the functionality's leakage.

### (c) Leakage privacy under active conditioning

The adversary's knowledge $K$ before the open: its own chosen/known contributions to $r''$ (all sets $T$ that exclude a corrupted party — everything except $T^{*} = C$), its $t$ shares of $r'$'s bits (information-theoretically independent of the bits by Shamir privacy), and its $t$ shares of $\bar{x}$. Condition on all of it. Subtracting the known part of the mask from $c$ leaves

$$
c_{\mathrm{unk}} \;=\; \mathrm{const} + \bar{x} + \underbrace{2^{m}\, r''_{T^*} + r'}_{M}
$$

where — fixing any one maximal unqualified set $T^{*}$ containing $C$ and handing the adversary every other contribution for free (valid: extra conditioning only helps it, and $\mathrm{SD}(X+Z, Y+Z) \le \mathrm{SD}(X, Y)$ for independent $Z$) — the $T^{*}$ contribution is uniform on $[0..2^w)$ (RISS path) and $r'$ uniform on $[0..2^m)$, independent. Because $M$ is a base-$2^m$ decomposition, $M$ is **exactly uniform** on $[0..2^{m+w})$. Shift bound: $\Delta(v + M, M) = v/2^{m+w} \le 2^{-\kappa_{\mathrm{eff}}}$; directly across two inputs, $\Delta = |v_0-v_1|/2^{m+w} \le 2^{-\kappa_{\mathrm{eff}}}$ (the statement's factor 2 is valid but loose). Post-verification precisions: (i) for $|C| < t$ multiple sets contain $C$ — the "exactly one unknown summand" phrasing applies to the *chosen* $T^{*}$, and the true bound only improves; (ii) the conditioning set $K$ also includes the RandBit generation transcripts (the opened squares), simulatable from public data and independent of the bit values — previously a silent premise; (iii) **scope**: this bound covers the transcript-plus-shares view only — the joint distribution of ($c$, later-opened $d$) is *not* $2^{-\kappa}$-close across inputs, by design: the carry is the functionality's declared probabilistic-rounding output, coupled to $c$ inside $\mathcal{F}$ (§§2–3), not hidden by the mask. Adversarially chosen corrupted contributions translate $c$ by a $K$-measurable offset; $\Delta$ is translation-invariant, so malicious choice buys nothing. On the PRSS path the $T^{*}$ contribution is a PRF output under one key shared across calls — see §6 for the correct single-global-hybrid accounting. ∎

### (d) Composable form and the real-to-hybrid step

*Hybrid-world UC:* S is forward-only (b), and the environment's input-adaptivity has no purchase: the value under `id_a` is $\mathcal{F}_{\mathsf{ABB}}$ state before $\Pi_{\mathsf{MO}}$'s first action, so no message of this session can influence the choice of its own input — the KLR delayed-input mechanism is excluded by the model, with no start-synchronization and no lock.

*Real-to-hybrid — revised after adversarial verification; the original threshold-timing argument is withdrawn.* The refutation: the adversary holds $t$ true points of the degree-$t$ $c$-polynomial before any honest party acts (its own input shares, environment-known, plus its mask shares on the globally consistent preprocessing polynomials), so the **first** honest $c$-share is the $(t+1)$-th point and interpolates $c$ completely — the old claim was off by exactly $t$. If later honest input shares were still freely choosable, this yields a working KLR-style attack: learn the mask from the first broadcast, then deal the remaining honest parties shares of a different polynomial agreeing at the published point, steering the carry deterministically.

The correct justification, which this codebase satisfies **structurally**: *every ABB handle's sharing polynomial is fully committed before the operation's first message.* Input handles to red ops are outputs of completed prior operations, and in every case the entire polynomial — not merely $t+1$ points — is a deterministic function of preprocessing-time randomness and already-public values: a Beaver product's output shares are $c_i + d\cdot b_i + e\cdot a_i + de$ with $d, e$ public and the triple polynomials fixed at preprocessing; an input-protocol value's shares are $(x+r) - [r]$ with $x+r$ RBC-public and $[r]$ a preprocessing polynomial; masks are preprocessing polynomials outright. At the moment any party emits a $c$-share there is no remaining freedom in any honest share — the environment's mid-session choice ranges over *which committed handles to use*, never over share values. Learning $c$ after the first honest broadcast is then harmless: $c$ is public output, governed by (c).

Three further obligations surfaced by verification: **(1) $\mathcal{F}_{\mathsf{Open}}$'s interface must reflect asynchrony** — adversarial delivery scheduling, $2t+1$-quorum output semantics — since an atomic synchronous Open is unrealizable in this network model; §5b is unaffected but the end-to-end statement must use the async Open. **(2) Sharing-polynomial uniformity**: for $|C| < t$ the Open simulator needs the $c_{\mathrm{pre}}$ polynomial conditionally uniform given corrupted shares and $c$; the RISS-converted $r''$ polynomial alone is *not* uniform (public recombination coefficients) — uniformity is supplied by the $r'$ bit-sharings' and the input's fresh polynomials, stated now as an explicit obligation on $\mathcal{F}_{\mathsf{PRandM}}$/$\mathcal{F}_{\mathsf{ABB}}$. **(3) Mask-index agreement is a privacy assumption, not bookkeeping**: if parties disagree on which pool entry serves a session (cursor skew), the adversary's $t$ shares become swing votes between two candidate openings — a selective-opening event no simulator matches — and persistent skew reuses entries across sessions, leaking mask differences outright. Agreement must be enforced: a session-derived index, or globally consistent ordering of mask-consuming operations.

**Implemented and proven**, via the session-derived index: `PRandIntNode::generate_prss_at` now takes the consuming operation's own `SessionId` as PRSS context instead of a bare pool cursor (`draw_prandint_shares` in `mod.rs`; `mpc/src/honeybadger/fpmul/prandint.rs`). Two different operations never share a keystream even though both start drawing at position 0, so whichever operation a node happens to service first no longer affects which secret a mask resolves to — no cross-node lock or execution-order agreement is needed. §6C proves collision-freeness and keystream separation of this addressing (adversarially verified), conditional on its conditions A–C.

## 6. Composition corollary: the leakage budget

Composition is by the UC composition theorem — not an ad hoc argument — applied in three steps. *Frame:* the §3 functionalities are extensions of $\mathcal{F}_{\mathsf{ABB}}$ by leaky commands, so the whole program is one protocol $\Pi_{\mathsf{prog}}$ designed for the extended ABB. The keyed real protocol is *not* subroutine-respecting — the PRSS key is joint state across every instance, the textbook Canetti–Rabin situation — which is exactly why Step 1 precedes composition; and the ABB board shared across instances is handled by stating §5's theorem in the exposed-shared-subroutine form (UC with global subroutines), which is what its environment quantification provides.

**Step 1 — realize the $\mathcal{F}_{\mathsf{PRandM}}$ instances, once, globally.** The real keystream implementation of all $N$ instances' $\mathcal{F}_{\mathsf{PRandM}}$ calls UC-emulates $N$ independent ideal $\mathcal{F}_{\mathsf{PRandM}}$ instances within a single term $\mathrm{Adv}^{(N)}_{\mathrm{PRF}}$, under §6C's conditions A–C. Two moves: (i) swap the $T^{*}$ PRF for a random function once, at the full $N$-query budget — per-invocation PRF hybrids are unprovable, since a reduction for one invocation cannot simulate the other invocations' real keystream without the key; (ii) a random function restricted to the instances' pairwise-disjoint address sets (§6C MI-1/MI-3) is *identically distributed* to independent per-instance random tapes, so rewrite the RF-hybrid protocol, at zero statistical distance, with each instance holding its own local tape — the rewritten protocol is subroutine-respecting, and it is the protocol Step 2's composition theorem is applied to, not the keyed one. This explicit rewriting is what makes joint-state (JUC) machinery unnecessary.

**Step 2 — $N$ exact replacements.** Replace the $\Pi_{\mathsf{MO}}$ instances by their leaky ABB-extension functionalities one at a time (Canetti's composition theorem, single-instance replacement iterated; the $i$-th replacement's environment subsumes $\Pi_{\mathsf{prog}}$, the adversary, and the remaining real instances — admissible because §5's theorem is stated in the exposed-shared-subroutine form, so Z's concurrent access to the shared ABB board and to other instances' $\mathcal{F}_{\mathsf{PRandM}}$ slices is within its quantification). Each replacement is exact: the simulator is straight-line and black-box with zero error (§5b), the instance's randomness is its own local tape disjoint from every other instance's (Step 1), and input commitment (§5d) closes the delayed-input channel. No simulation error accumulates and no cross-instance interaction arises, regardless of the adversary's interleaving. After $N$ replacements — $N$ the number of masked-open invocations, counted exactly as in the worked example below, not the number of top-level operations — $\Pi_{\mathsf{prog}}$ runs with every masked open an ideal $\mathcal{F}$-call.

**Step 3 — leakage accounting.** The composite still leaks each instance's $c$. Swapping each leaky $\mathcal{F}$ for its input-independent-leakage variant costs at most $2^{-\kappa_{\mathrm{eff}}}$ per instance by §5c — a bound that holds for every fixed input, hence under adaptively chosen, correlated inputs across instances — $N\cdot 2^{-\kappa_{\mathrm{eff}}}$ in total. Hence (the budget below inherits §6C's conditions A–C through Step 1):

**Corollary.** A protocol making $N$ calls to leaky functionalities of the §3 family is distinguishable from the same protocol with input-independent leakage by advantage at most

$$
\mathrm{Adv}^{(N)}_{\mathrm{PRF}} \;+\; N \cdot 2^{-\kappa_{\mathrm{eff}}}
$$

**Note (provenance of this accounting).** The three-step structure incorporates the post-verification corrections that previously stood here: the PRF term is a single global hybrid, never $N$ per-call terms (Step 1), and the statistical hybrids are valid under adaptive inputs because §5c's bound is worst-case over inputs (Step 3). On the RISS path the PRF term vanishes and the masks are genuinely independent uniform draws.

This is the interface the composed-layer audit consumes. **Worked example (numbers corrected after verification):** one `div_fixed` (FXDiv at $k = 2f$, $\theta = \lceil\log_2(k/3.5)\rceil = 5$ across $k \in [64..112]$) makes $2\theta+1 = 11$ TruncPr calls — but TruncPr is not the dominant leak: the Norm/SufOr stages' per-bit masked opens dominate, giving $N \approx 137$ ($k = 64$) to $\approx 233$ ($k = 112$) leaky calls per division. At $\kappa_{\mathrm{eff}} = 40$ the total statistical term is $\approx 2^{-31.9}$ to $2^{-31.1}$ per division — the earlier "$< 2^{-32}$" claim was wrong at this parameter. $\kappa_{\mathrm{eff}} \ge 44$ restores comfortable margin ($\le 2^{-36}$ per division); $\kappa$ is a configuration constant, so this is a parameter choice, not a protocol change. The PRSS path adds the global $\mathrm{Adv}^{(N)}_{\mathrm{PRF}}$ term on top.

Two boundary rules the corollary imposes on callers, both already true in the code but now proof obligations rather than habits:

- A revealed $c$ must never be used in secret-dependent control flow (it is public data; using it in *public* control flow, as BitDec/TruncPr do locally, is fine and accounted).
- Masks are single-use: a pool entry consumed by one call must never serve another (cursor discipline); reuse would correlate two leaks and void the hybrid argument.

**The stacked-layer lift: per-operation leaky-call counts.** Every operation above the red core is a composition of the three proven leaky functionalities plus perfect-core calls (zero budget), so its theorem follows from the UC composition theorem with budget $N_{\mathrm{op}}\cdot 2^{-\kappa_{\mathrm{eff}}}$. The counts come from the code's own preprocessing-demand accounting (`preprocessing.rs` `demand_for_*`, `comparison/mod.rs` `*_prep_counts`): each PRandInt draw is consumed as the high mask of exactly one masked open, so $N_{\mathrm{op}}$ = the op's prandint count.

| Top-level op | N (leaky opens) | Breakdown |
| --- | --- | --- |

| `mul_fixed(f)` | 1 | one TruncPr (1 triple + $f$ RandBits are perfect-core) |
| `div_with_const_fixed(f)` | 1 | one TruncPr |

A workload's total budget is $\sum N_{\mathrm{op}}\cdot 2^{-\kappa_{\mathrm{eff}}}$ + one global $\mathrm{Adv}_{\mathrm{PRF}}$ term at the total query count. Per-op functionality statements are mechanical from here: each stacked op's $\mathcal{F}$ leaks the tuple of its sub-opens' leaks and stores the exact (or TruncPr-rounded) result; the simulator is the concatenation of the sub-simulators, straight-line because each is.

## 6A. Stacked-layer functionality statements (list item 5)

Each operation below is a composition of already-proven functionalities — $\mathcal{F}_{\mathsf{TruncPr}}$ / $\mathcal{F}_{\mathsf{Mod2}}$ / $\mathcal{F}_{\mathsf{KOrCL}}$ (leaky, this doc) and the perfect core (Perfect-Open Lemma, zero budget) — glued by local linear arithmetic. By the UC composition theorem, each realizes the functionality stated below with a straight-line simulator that is the concatenation of the sub-simulators, and leakage budget $N \cdot 2^{-\kappa_{\mathrm{eff}}}$ per call with the $N$ from §6's table. No new simulation argument is required anywhere in this section; what each paragraph pins down is the *output law* and the *leak tuple*.

- **$\mathcal{F}_{\mathsf{PreMod2m}}(k, m)$** — input $\bar{a} \in \mathbb{Z}_{\langle k \rangle}$; output exactly $\bar{a} \bmod 2^m$ (deterministic). Leaks: one PRandM-masked open (the main $c$) plus the $m$ degenerate Mod2-style opens inside PreBitLT; PreBitLT's multiplications are perfect Beaver. $N = 1 + m$. The borrow bit $u$ is *computed exactly* by PreBitLT ($u = [c' < r']$, a comparison of a public value against the shared mask bits), so unlike TruncPr there is no probabilistic rounding — but $u$'s value is determined by $(c, r')$ exactly as in the §2 coupling, so the functionality derives it from the same internal randomness as the leak. Output law: $\bar{a} \bmod 2^m = c' - r' + u \cdot 2^m$, verified against Catrina 2018 Protocol 9 during the faithfulness pass.
- **$\mathcal{F}_{\mathsf{BitDec}}(k, m)$** — input $\bar{a}$; output handles to the $m$ least-significant bits of $\bar{a}$'s two's-complement representation (deterministic). Leaks: its masked open(s) per the demand accounting; the bit-shares consumed are RandBits (perfect) and BitAdd's carry chain is Beaver (perfect). Output law: $(r + c) \bmod 2^m$ equals the two's-complement low bits — Protocol 10's identity, including the $m = k$ sign-bit case, verified during the faithfulness pass.
- **$\mathcal{F}_{\mathsf{LTZ}}(k)$** — input $\bar{a}$; output exactly $[\bar{a} < 0]$ (deterministic). Composition: PreMod2m$(k, k-1)$ + local ($s = -\text{Trunc}$ via the mod). $N = k$. Leak tuple = PreMod2m's.
- **$\mathcal{F}_{\mathsf{EQZ}}(k)$** — input $\bar{a}$; output exactly $[\bar{a} = 0]$ (deterministic). Composition: one $k$-bit masked-sum open, then $\mathcal{F}_{\mathsf{KOrCL}}$ on the XOR'd bits, then local complement. $N = 2$. Leak tuple = the two masked opens.
- **$\mathcal{F}_{\mathsf{AppRec}}$ / $\mathcal{F}_{\mathsf{FXDiv}}(k, f)$** — inputs $\bar{a}$, $\bar{b}$ (divisor nonzero); output the Goldschmidt approximation of the quotient with the error bound $(\theta+1) \cdot 2^{-f}$ established in the faithfulness pass — *not* an exact function of the inputs alone: it is the deterministic function of (inputs, the TruncPr carry bits), each carry coupled to its own leak exactly as in $\mathcal{F}_{\mathsf{TruncPr}}$. The functionality therefore computes the full algorithm internally with its own mask randomness and leaks the tuple of all sub-opens (Norm's BitDec/PreOR stage, AppRcr's TruncPr, 2 TruncPr per iteration). $N = 2k + 2\theta - 1$ ($137\ldots 233$ over $k = 64\ldots 112$). Sub-calls into SufOr/SufMulInv/PreBitLT resolve into the same three leaky cores plus perfect Beaver — nothing outside the proven set.

**Boundary conditions carried up from the cores:** every multiplicatively-masked value nonzero (PreMulC/KOrCS precondition — satisfied structurally in these call paths); masks single-use via cursor discipline; $m \le k-1$ where applicable.

## 6B. Formal obligations (list item 6)

**$\mathcal{F}_{\mathsf{Open}}$, async interface.** On `(open, id)` with value $v$ under `id` at degree $d$: $\mathcal{F}_{\mathsf{Open}}$ immediately leaks $v$ to the adversary; it delivers $v$ to each honest party only when the adversary schedules that party's delivery. Guarantees: (i) *integrity, unconditional* — any delivered value equals $v$ (no execution delivers a wrong value; Perfect-Open §2's code audit is the realization-side witness); (ii) *liveness, degree-dependent* — if $d + t + 1 \le n - t$ (i.e., honest shares alone meet the decode threshold; true for $d = t$ at $n \ge 3t+1$), the adversary may delay but not prevent delivery; if $d + t + 1 > n - t$ ($d = 2t$ at $n = 3t+1$), the adversary may withhold its shares and stall delivery indefinitely — abort, never corruption. All end-to-end theorems in this document and the Perfect-Open Lemma are stated against this interface; an atomic synchronous Open would be unrealizable in this network model and would void the real-to-hybrid step.

**$\mathcal{F}_{\mathsf{PRandM}}$, sharing-polynomial uniformity.** $\mathcal{F}_{\mathsf{PRandM}}$ hands out not just values but *sharings*, and the Open simulators need the sharing polynomials' free dimensions to be exactly uniform conditioned on the adversary's shares and dealt contributions. Obligation: (i) RandBit outputs and $r'$ bit-sharings are fresh degree-$t$ sharings whose polynomials, conditioned on any $t$ shares, are uniform on the residual dimensions — satisfied by RanSha's full-field `DensePolynomial::rand` dealing; (ii) degree-$2t$ zero-shares are uniform on $\{\deg \le 2t, p(0) = 0\}$ conditioned on the adversary's own dealt contributions — satisfied by the hyperinvertible combination (BTH08 Construction 1, confirmed in code), **now that the `zero_share.rs:613` verifier fix ($\le 2t$, list item 16, commit `1de29e8`) has landed**: the prior exact-degree test let the OK bit depend on honest randomness (a trailing-zero leading coefficient silently lowers the reported degree), biasing the residuals by $\Theta(t/q)$ and breaking exactness; the degree-$\le$ check does not share that flaw; (iii) the RISS-converted $r''$ polynomial is *not* uniform on its own (public recombination coefficients) and must never be the sole source of residual uniformity at any open — at every current degree-$2t$ open the zero-share supplies it, and at every degree-$t$ open the input's own fresh polynomial does; any new open shape must re-check this.

## 6C. Mask-index agreement: collision-freeness and keystream separation (items 19a/19b)

This section discharges §5d obligation (3) as a proof, not a mechanism description. The claim has two halves: (19a) no two mask draws — on one node or across honest nodes — ever address the same keystream position for different logical values, under active corruption; (19b) distinct addresses yield per-set contributions that are jointly pseudorandom, so the §6 single-global-hybrid accounting applies unchanged.

**Mechanism recap.** A mask is addressed by the pair (ctx, p): ctx = `context_bytes(session_id)` is a fixed-width 16-byte encoding of (`calling_protocol`, `instance_id`, `exec_id`, `sub_id`, `round_id`) plus a reserved domain-separator byte (0x01 for masks; any future PRSS consumer takes a different value), and $p \in [0..N_{\mathrm{op}})$ is the absolute position in the keystream for ctx. The KDF's output-length parameter is held constant (SP 800-108 L fixed), so the keystream for (key, ctx) is one fixed sequence regardless of requested range — position p denotes the same value no matter how it is reached. Each top-level red operation (`mul_fixed`, `div_with_const_fixed`, `div_fixed`, `ltz_on_share`, `eqz_on_share`) constructs its own `session_id` from a per-protocol-type local counter, draws its entire flat mask batch $0..N_{\mathrm{op}}$ in a single call under that `session_id` (always at start = 0), and hands sub-protocols disjoint slices of the batch — sub-protocols never draw.

**Lemma MI-1 (per-node injectivity, unconditional).** On a single honest node, the map from mask draws to addresses (ctx, p) is injective. *Proof.* Within one operation: exactly one draw call produces positions $0..N_{\mathrm{op}}$, and downstream consumption (`take_prandm_prep`, `build_premod2m_prep`, `build_fpdiv_prep`) splits the batch into disjoint prefixes — no position is handed out twice. Across operations of the same protocol type: `exec_id` values are produced by a mutex-guarded monotonic counter; `pack_slot` carries the full 64-bit value and the accessor recovers it exactly (no truncation — verified), and the counter faults at wraparound (`u64::MAX` is issued once, then the counter poisons and every later draw errors) rather than re-issuing 0, so `exec_id`s are pairwise distinct over the node's lifetime. Across protocol types: `calling_protocol` differs. One restriction: `context_bytes` ignores the `SessionId`'s `extra_bits` field and collapses unknown protocol bytes to 0xFF, so the encoding is injective only over the draw-site image — which suffices, because all five draw sites construct a fresh `SessionId::new` with a valid protocol literal, zero `extra_bits`, and `sub_id` = `round_id` = 0, and injectivity is only claimed there. Across executions: `instance_id` differs — condition C below. ∎

**Lemma MI-2 (adversarial non-influence, unconditional).** No field of any mask address is a function of adversarial input. *Proof.* `calling_protocol`, `sub_id`, `round_id` are literals at the call site. `exec_id` is read from the local counter, which is advanced only inside the five top-level operation entry points — by code audit, no message-processing path (`process()` on either the node- or client-facing side, and every sub-protocol handler they route to) calls `get_next` on any of the five mask-relevant counters; `run_preprocessing` advances only non-mask counters, and the PRandInt counter it touches feeds the RISS *bootstrap* session only, whose key derivation is domain-separated from keystream generation by a distinct KDF label. `instance_id` is deployment configuration fixed before the first message. The adversary's only remaining lever is scheduling: delaying messages delays operations but cannot reorder them, because a node runs one operation at a time and the next operation starts only when the program issues it — the per-type call sequence is program order, not arrival order. Message *content* never reaches the address computation. (Contrast with the refuted pool-cursor design, where the cursor was advanced by amounts dependent on locally observed pool depth — a quantity the adversary could skew per-node through selective message delay. That channel is gone for masks: the address depends on *how many operations of this type the program has issued*, never on *what the node has received*.) ∎

**Lemma MI-3 (cross-node agreement).** Under conditions A–C, every honest node computes the identical address set for the $k$-th operation of each protocol type:

- **A (same program order and configuration).** All honest nodes execute the same global sequence of top-level operations with the same public parameters, one operation at a time, under identical node configuration — explicitly including `precision` and `statistical_security`, hence `mask_bits`: a `mask_bits` mismatch derives shares of a different secret with no message exchange left to catch it, and no runtime cross-node check exists. The one-at-a-time discipline is load-bearing and deliberate, not incidental: counters are shared across the node's task clones, so two *concurrent* same-type operations would receive `exec_id`s in local scheduler order, nondeterministic across nodes. (For this lemma alone the per-protocol-type projection of the sequence would suffice — mask addresses of different types live in disjoint context namespaces — but the system's other preprocessing consumers need the global form; see the scope note.)
- **B (all-or-nothing advancement).** An operation that fails on any honest node — timeout, preprocessing shortfall, any Err before or after its `get_next` — terminates the execution for all honest nodes. No partial retry: the execution is not resumed from a state where some honest nodes advanced a counter and others did not.
- **C (`instance_id` uniqueness against one key set).** All parties of one execution share one `instance_id`, and no `instance_id` is ever reused against the same PRSS keys (§7's SID-uniqueness item; the `InstanceIdRegistry` supplies per-deployment enforcement, and a fresh RISS bootstrap — new keys — is the alternative discharge where restarts are needed).

*Proof.* By induction on the per-type call sequence. Base: all counters start at 0. Step: if all honest nodes agree on the counter value before the $k$-th type-$P$ call, they construct the same `session_id` (same protocol literal, same `exec_id` by hypothesis, same `instance_id` by C, `sub_id` = `round_id` = 0 at every draw site), and $N_{\mathrm{op}}$ is a deterministic function of the operation's public parameters (`demand_for_fpdiv(k,f)`, `demand_for_ltz(k)`, `demand_for_eqz(k)`, or the constant 1; the counts were checked against the prep builders' exact consumption) — identical by A, as is the draw width `mask_bits`. Both the context and the position range therefore agree. The counter advances exactly once on every honest node (A guarantees each issues the call; B guarantees the execution dies rather than proceeding if any node fails to complete it), restoring the hypothesis. ∎

**Lemma MI-4 (keystream separation, 19b).** Assume every draw satisfies $N_{\mathrm{op}} \cdot \lceil w/8 \rceil < 2^{37}$ bytes per context — discharged with enormous slack by the demand formulas ($N_{\mathrm{op}} \le 2k + 2\theta - 1 \lesssim 240$ values of $\le 32$ bytes; the KDF's u32 block counter would alias only past $2^{37}$ bytes $\approx 137$ GB of one context's stream, and no production path can request it since start is pinned to 0 and count comes from the demand model, not from input). Then distinct addresses yield per-set contributions that are jointly indistinguishable from independent uniform values on $[0..2^w)$, up to one global $\mathrm{Adv}_{\mathrm{PRF}}$ term. *Proof.* Each address (ctx, p) maps to a distinct PRF input: ctx is in the HMAC input of every block, and under the boundedness premise distinct positions within one ctx read disjoint bytes of counter-mode output at distinct (non-wrapped) block counters (the per-draw width is fixed because every draw site uses the node's single configured `mask_bits`, and MI-1's single-draw-per-session rule precludes the same ctx ever being read at two widths). By MI-1 the address map is injective, so all PRF inputs across the whole execution are distinct; replace the PRF with a random function once (the §6 single global hybrid) and the per-set contributions are exactly independent uniform on $[0..2^w)$ — the top-byte masking yields exact uniformity, and no modular reduction occurs because `max_mask_bits` keeps every aggregate below the field modulus. Two precisions: (i) what is uniform is each *per-set contribution* $f_T$(ctx, p); the *aggregate* mask $M = \sum_T f_T$ lies in $[0..C(n,t) \cdot 2^w)$ and is deliberately not uniform — §5c's hiding argument never needs it to be: it conditions on every contribution the adversary can compute and uses only the uniformity of the single unknown contribution $f_{T^{*}}$, which is exactly what this lemma delivers. (ii) The reserved domain-separator byte extends the argument across any future second PRSS consumer without re-proof. ∎

**Consequence for §5d obligation (3).** The selective-opening attack required the adversary's $t$ shares to act as swing votes between two candidate masks for one open. By MI-1–MI-3, at every open all honest parties mask with the same single candidate — and honest shares alone pin the decoded value regardless of what the corrupt shares vote for: robust reconstruction accepts a degree-$t$ polynomial only on $\ge 2t+1$ matching shares, of which at least $t+1$ are honest, and two distinct degree-$t$ polynomials cannot share $t+1$ points; a competing candidate could collect at most $t$ honest + $t$ corrupt = $2t < 2t+1$ matches. (Unique-decoding check: $t$ errors $\le (n - (t+1))/2 = t$ at $n = 3t+1$.) Corrupt shares can therefore delay or stall an open, never steer its value — there is no second candidate to swing toward. The quantity that could skew in the pool design (a shared mutable cursor) no longer exists.

**Failure analysis — why B and C are privacy-critical, and what exactly breaks.** *B violated (counter skew).* Suppose node $i$ errors before `get_next` while the others advance, and the execution is resumed: node $i$'s subsequent type-$P$ addresses are shifted by one, so node $i$ masks operation $Y$'s value with the position the others used for operation $X$. This does **not** reliably announce itself as an abort: the adversary can align its $t$ shares with the $2t$-node majority, so the open *succeeds* (node $i$'s deviating share is absorbed within the $t$-error decoding radius) and the execution continues with node $i$ silently one operation behind. The leak is then exact and repeats at every subsequent type-$P$ open, at the adversary's option — deviate to force an abort, or align to keep harvesting: the corrupt coalition $(|C| = t, T^{*} = C)$ computes every PRSS contribution except $f_{T^{*}}$; from the broadcast honest $c$-shares plus its own computable shares it fully determines the mixed polynomial of each skewed open, extracts the mask-difference from node $i$'s deviating point, and cancels it between consecutive opens — yielding the linear relation $x - y$ between the two masked secrets, and transitively, pairwise differences of every subsequent masked value of that type, forever. No simulator can produce these relations, and nothing in-band detects the skew. *C violated (`instance_id` reuse against the same keys).* Strictly worse, and simpler: the counters restart at 0, the contexts repeat, and the keystream is bit-identical across the two executions, so the $k$-th opens satisfy $c_1 - c_2 = x_1 - x_2$ — the difference of the two secrets is read directly off the two public opens, by anyone observing the broadcasts, with no corrupted party needed at all. This is outright mask reuse, the exact event §6's single-use rule exists to exclude. Hence: a failed red operation must kill the execution (B), and an `instance_id` must never meet the same PRSS keys twice (C). Both are stated preconditions of MI-3, not consequences of the mechanism.

**Scope note.** Condition A must be read as the *global* operation-sequence agreement, because this lemma's improvement is local to the mask subsystem: triples, RandBits, zero-shares, rand-inv pairs, and PreMulC bundles are still FIFO-drained from shared pools with nothing binding a pool entry to an operation's identity, so two honest nodes that interleave operation *types* differently would assign different triples to the same logical multiplication — a correctness break that also voids the simulation argument. The mask subsystem alone now tolerates the weaker per-type projection of A; extending the same session-derived binding to the remaining pools is the path to actually weakening the deployment assumption, and is noted as follow-on work, not assumed.
