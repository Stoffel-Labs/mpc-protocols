# Perfect-Open Lemma

2026-10-31 · Garry

Companion to the Masked-Open Lemma: the stand-alone perfect-security write-up for the arithmetic core, in the form KLR Thm 1.2 consumes (perfect + straight-line black-box $\Rightarrow$ UC under concurrent composition).

## 1. Scope

**Covers:** `mul` (Beaver), `triple_gen`, `MulPub`, `RandBit`, `RandInvPair`, `PreMulC`, `KOrCS` — the operations classified *perfect* whose active-security argument exists in no paper (their source papers are semi-honest; the active half is this codebase's robust-reconstruction substitution). `input` and `output` are covered as degenerate cases (a single masked or plain open).

**Explicitly out of scope:** `RanSha`/`RanDouSha`/`zero_share` generation (verifier/abort structure, not an open — their proofs are the cited DN07/BH08 constructions, handled by the provenance-verification track) and the decoding machinery itself (`robust_interpolate`, `batch_recon` — assumed here as the realization of ideal Open; same real-to-hybrid step as the Masked-Open doc §5d).

**Model:** identical to Masked-Open §1 — static active adversary, $|C| \le t < n/3$, security with abort, ($\mathcal{F}_{\mathsf{ABB}}$, pools, ideal Open)-hybrid, where $\mathcal{F}_{\mathsf{ABB}}$ is the arithmetic black box (Damgård–Nielsen 2003): the ideal functionality that holds secret field elements under public handles, computes linear operations and products on them, and reveals a value only when Open is called on its handle. Values with no statistical mask anywhere; the target property is **perfect stand-alone security with a straight-line black-box simulator**, which is exactly the hypothesis of KLR Thm 1.2 (perfect + straight-line $\Rightarrow$ secure under concurrent general composition $\iff$ UC). The lemma therefore closes the perfect half of the concurrency claim once its own preconditions (§6) are discharged.

## 2. The degree dichotomy

At n = 3t+1, "robust reconstruction" means two different things depending on the degree of the sharing being opened, and the proofs must not conflate them:

- **Degree-t opens** (Beaver's $d = a-x$, $e = b-y$; PreMulC's and KOrCS's online reveals): the code is an RS codeword of dimension t+1 in $n \ge 3t+1$ coordinates — minimum distance $\ge 2t+1$, so up to t erroneous shares are **corrected**. A cheater's wrong share has literally no effect: not on the value, not on liveness. These opens are fully robust.
- **Degree-2t opens** (`MulPub`'s product, `triple_gen`'s v, `RandBit`'s $r^2$, `RandInvPair`'s c): dimension 2t+1 in n = 3t+1 coordinates — minimum distance t+1, which **detects** t errors but cannot in general correct them. Two consequences, both load-bearing:
    - **Safety is still perfect:** any two degree-2t polynomials agreeing on the 2t+1 honest coordinates are identical, so no choice of t corrupted shares can cause a *wrong* value to be accepted — the decoder either outputs the true value or fails to find a consistent codeword.
    - **Liveness is not:** t strategically wrong shares can prevent the quorum from assembling, stalling the open. This is precisely the HBMPC paper's own Table-1 caveat (offline phase "makes progress only when all n nodes are responsive"), re-derived here at the proof level — and it is *compatible* with the security claim, because the entire program is security-with-abort: the functionality may abort, it may never output a wrong or leaky value.

(For $n > 3t+1$ the degree-2t case regains correction capacity $\oslash((n-2t-1)/2\ \text{errors})$ and the dichotomy softens; the statements below are made at the worst case n = 3t+1.)

## 3. Lemma statement

**Protocol $\Pi_{\mathsf{PO}}$ (hybrid).** Parties hold handles in $\mathcal{F}_{\mathsf{ABB}}$ (the arithmetic black box: the ideal functionality storing secret values under public handles; see §1), compute a new handle by local linear operations and/or local share-products (plus, for degree-2t opens, addition of a fresh degree-2t zero-share), and invoke Open on it; local post-processing on the opened value and existing handles produces the output handle(s).

**Lemma.** In the ($\mathcal{F}_{\mathsf{ABB}}$, $\mathcal{F}_{\mathsf{pools}}$, ideal Open)-hybrid, against a static active adversary corrupting $|C| \le t < n/3$ parties, $\Pi_{\mathsf{PO}}$ realizes its leak-free ideal functionality with **zero simulation error**, via a straight-line black-box simulator, provided every opened value $V$ is one of:

- **Type A — jointly-uniform reveal.** The *joint* vector of all values the protocol opens, conditioned on the adversary's prior view and the declared outputs, has an exactly-sampleable, input-independent distribution. Sufficient criterion: the map from the fresh masks to the opened vector is a **triangular bijection with nonzero multipliers for every fixing of the inputs**, so the opened vector is exactly uniform on $(\mathbb{F}^*)^N$. Instances: Beaver's $(d, e)$; PreMulC's joint $(u_1..u_k, m_1..m_k)$; KOrCS's joint $(c_1..c_k, d_1..d_k)$.
- **Type B — output reveal.** $V$ *is* the functionality's declared public output for this call. Instances: MulPub's $a \cdot b$, triple_gen's $v = ab - r$, RandInvPair's $r \cdot r'$.
- **Type C — exactly-sampleable derived reveal.** $V$ is neither uniform nor the output, but has an exactly known, input-free distribution the simulator can sample consistently with the output. Instance: RandBit's $u = r^2$ — uniform on the nonzero quadratic residues; the simulator receives the bit $\beta$ from $\mathcal{F}$, samples $r$ uniform on the $\beta$-consistent half of $\mathbb{F}^*$ (exactly $(q-1)/2$ elements for each $\beta$, since squaring is 2-to-1 and the code's root extraction is a deterministic function of $u$ alone), and publishes $r^2$.

and every protocol branch on an opened value is one of: (i) public post-processing identical at all parties, or (ii) an abort/drop triggered by an event ($V = 0$) whose probability is a fixed function of pure fresh randomness, independent of all inputs and all prior state.

**Addendum (leakage interface).** $\Pi_{\mathsf{PO}}$ contributes **zero** to the leakage budget of the Masked-Open doc's §6: Type-A reveals are exactly input-independent; Type-B reveals are the output itself. This is the formal content of the "perfect" classification.

## 4. Proof

**Simulator S, straight-line.** S holds the corrupted parties' interfaces to $\mathcal{F}_{\mathsf{ABB}}$ and the pools (their t shares of every handle, their registered contributions) — identical in both worlds by definition of the hybrid functionalities. Per Open:

1. **Obtain the value.** Type A: S samples $V$ itself from its exact distribution — uniform on $\mathbb{F}$ (additive mask) or $\mathbb{F}^*$ (multiplicative) — using no input; this is legitimate precisely because the real $V$ is exactly that distribution conditioned on everything the adversary has seen (full-field single-use mask). Type B: the functionality hands S the public output $V$.
2. **Produce the share view.** Degree-t opens: $V$ at position 0 plus the t corrupted shares are t+1 constraints on a dimension-(t+1) polynomial — it is *fully determined*; S computes every honest share exactly. No sampling, no error. Degree-2t opens: t+1 constraints on dimension 2t+1 leave t residual dimensions; in the real world these are uniform **because of the fresh degree-2t zero-share added to the product** — its non-constant coefficients are full-field uniform even conditioned on the adversary's own dealt contributions (at least one honest dealer's contribution is unknown and uniform, and uniformity is preserved under known shifts). S samples the residual t dimensions uniformly and computes honest shares from the resulting polynomial. Exact in both cases.
3. **Abort/drop events.** The $V = 0$ branches (RandBit drop, RandInvPair/PreMulC abort) fire with probability determined by fresh randomness only ($\approx 1/q$, input-independent). S's own sampling of $V$ in step 1 reproduces the event with identical probability and identical observable consequences — the event is part of the sampled value, not a separate coin.
4. **Post-processing.** All remaining steps are public arithmetic on ($V$, handles) identical at every party; S performs them as the protocol does. Outputs stored under handles are derived from the same $V$ in both worlds, so the joint of (view, functionality state) — hence every later operation on the outputs — is identically distributed.

**Why active cheating adds nothing.** In the hybrid, the only adversarial moves are: inputs to pools (registered, known to S), and Open behavior — which the ideal Open resolves per §2: degree-t, corrected (no observable event); degree-2t, true-value-or-stall (stall is an abort the simulator relays; with-abort functionality). There is no message in $\Pi_{\mathsf{PO}}$ whose content a corrupted party controls beyond these.

**Perfectness and KLR.** Every step above is exact — no statistical slack anywhere, matching the classification. S never rewinds, uses only oracle access to the adversary, and processes events in protocol order: straight-line black-box. These are precisely the hypotheses of KLR Thm 1.2, so — once §6's preconditions are discharged — each $\Pi_{\mathsf{PO}}$ instance is secure under concurrent general composition, equivalently UC, with no further argument. ∎

**Verification notes on the proof (post-adversarial review).**

- *Degree-2t safety — confirmed against the actual decode code.* Every acceptance path (`recover_secret` entry gate, optimistic FNT, OEC loop, Gao re-verification, `batch_recover_secret`) requires $\ge \text{degree}+t+1$ consistent shares, which forces $\ge \text{degree}+1$ honest-consistent points on a degree-bounded candidate — wrong acceptance impossible; at n = 3t+1 degree-2t opens have exactly zero correction capacity, matching "safe-but-abortable" (file:line audit in the verification record). All thresholds are degree-parameterized, so $n > 3t+1$ regains correction without changing soundness. No path falls back to non-robust reconstruction for these opens.
- *Zero-share residual uniformity — structurally sound, but "zero error" is conditional on a one-line code fix.* The hyperinvertible combination (BTH08 Construction 1, not plain Vandermonde) delivers exactly full-rank uniformity, with zero slack in the dimension budget ($(2t+1) \cdot t$). However, the zero-share verifier's OK bit uses an **exact-degree test** (`poly.degree() == 2t`, zero_share.rs:514); the leading coefficient is a nonconstant functional of the kept residuals, so conditioning on the broadcast OK bits biases them by $\Theta(1/q)$ each — total simulation error $\Theta(t/q)$, not zero. Astronomically small, but KLR Thm 1.2 consumes *perfect*, and statistical-with-straight-line provably does not compose (Thm 1.1) — so the clean resolution is the code fix: **accept degree $\le 2t$ in the verifier predicate**, which makes the pass bit invariant under adding the honest codeword (a function of adversarial messages only), restoring exact uniformity. The analogous exact-degree checks in `ran_dou_sha`'s verifier (`threshold != poly.degree()`) should be reviewed for the same pattern during the provenance track.
- *Residual dimension for $|C| < t$:* the free dimension at a degree-2t open is $2t - |C|$, not t; the simulator samples the actual count. (Evaluation points are domain elements — distinct, never 0 — so the constraint system is always full rank.)
- *Abort probabilities:* the offline zero events ($u_i = 0$, $c_j = 0$) occur with probability $\approx 2/q$ per pair (either factor zero), not $\approx 1/q$ — cosmetic, input-independence unaffected.

## 5. Per-op instantiations

- **`mul` (Beaver).** Two Type-A degree-t opens: $d = a-x$, $e = b-y$, with a, b independent fresh full-field pool values, each appearing in exactly one opened expression. Output handle $de + d \cdot [b] + e \cdot [a] + [c]$ is public arithmetic on $(d, e)$ and existing handles. $\mathcal{F}_{\mathsf{Mult}}$ leaks nothing; simulator samples $d, e \leftarrow \mathbb{F}$ uniformly.
- **`triple_gen`.** One Type-B degree-2t open: $v = ab - r$ with r the fresh degree-2t RanDouSha mask; v is simultaneously Type A (uniform via r) — doubly covered. Output $[c]_t = [r]_t + v$. Degree-2t rules apply: safe-but-abortable.
- **`MulPub`.** One Type-B degree-2t open of $a \cdot b$ plus the fresh degree-2t zero-share (which does the §4 step-2 work). The functionality's output *is* the opened value; nothing else is revealed. Callers feeding it only fresh randomness (all current callers) inherit input-independence of the revealed value trivially.
- **`RandBit`.** MulPub instance at $a = b = [r]$, r fresh uniform, then local: $v = (r^2)^{-(q+1)/4}$, $[b] = (v[r]+1)/2$. Simulator: receive the output bit $\beta$ from $\mathcal{F}_{\mathsf{RandBit}}$, sample r uniform on $\mathbb{F}^*$ conditioned on the extraction yielding $\beta$ (exactly half of $\mathbb{F}^*$ for each $\beta$ — the $\pm r$ quadratic-residue ambiguity), publish $r^2$ via the §4 mechanics; the drop event ($r = 0$, probability $1/q$) is reproduced by the same sampling. Exact because squaring is exactly 2-to-1 on $\mathbb{F}^*$.
- **`RandInvPair`.** MulPub instance at $([r], [r'])$ independent fresh uniforms; opened $c = r \cdot r'$ is Type B and, given either factor, nonzero-uniform; abort on $c = 0$ (probability $< 2/q$) input-independent. Local output $[r^{-1}] = c^{-1}[r']$.
- **`PreMulC`.** Offline: MulPub instances on fresh $(r_i, s_i)$ with abort-on-zero — covered above. Online: the chain $m_1 = r_1 \cdot a_1$, $m_i = (r_i/r_{i-1}) \cdot a_i$ opened at degree t. **Joint, not just marginal, claim:** conditioned on nonzero inputs (documented precondition), the map $(r_1, \dots, r_k) \mapsto (m_1, \dots, m_k)$ is a bijection of $(\mathbb{F}^*)^k$ for any fixed nonzero inputs — each $m_j$ introduces exactly one fresh independent $r_j$ — so the opened vector is exactly uniform on $(\mathbb{F}^*)^k$, jointly. Simulator samples the whole vector uniformly.
- **`KOrCS`.** Same chain structure with $(r_j, r_j^{-1})$ pairs and $a = 1+\sum b_i \in \{1..k+1\}$ nonzero by construction: $d_1 = a \cdot r_1$, $d_j = r_{j-1}^{-1} \cdot a \cdot r_j$. Same bijection argument $\Rightarrow$ jointly uniform on $(\mathbb{F}^*)^k$. Padding slots open public constants (simulated as such).
- **`input` / `output` (degenerate cases).** `input`: the broadcast $x + r$ is Type A (r full-field, revealed only to the owning client pre-broadcast — the client knows x); `output`: the reveal to the recipient is Type B (the output itself, to its intended receiver only).

**Verification notes on the instantiations.**

- *RandBit — code correction:* the implementation does **not** use the paper's `u^{-(q+1)/4}` exponentiation (BLS12-381's scalar field has $q \equiv 1 \bmod 2^{32}$, so $(q+1)/4$ is not even an integer); it calls ark-ff's `sqrt()` — deterministic Tonelli–Shanks, a pure function of u. Any deterministic-in-u root convention yields the exact 1/2–1/2 split over $\{\pm r\}$, so the simulator's conditional sampling is exact regardless of convention; all parties extract the same root from the same robustly-opened u, so outputs are consistent. The drop-on-zero count and positions are i.i.d. Bernoulli$(1/q)$, input-independent, exactly reproducible; a non-residue u (possible only if safe-open were already broken) aborts — never wrong acceptance.
- *PreMulC / KOrCS — joint claims verified:* $(u, m)$ and $(c, d)$ are exactly uniform on $(\mathbb{F}^*)^{2k}$ jointly, via explicit inverse maps; the cross-reveal correlations the single-use worry pointed at are absorbed by the genuinely single-use second factors $(s_i, r'_j)$. On precondition violation the leak is precisely the **zero-position pattern** $\{i : a_i = 0\}$ — positions included — with remaining opens staying uniform; the code's documented caveat (pre_mulc.rs:421–434) states this accurately.
- *Beaver — single-use is enforced by pool drain and caller discipline, not by the API:* `Multiply::init` would accept a second init on the same session with different inputs; no current path does this (triples drained once, fresh session ids, retired sessions refuse resurrection, retries re-draw), but it is an assumption on callers, now stated. Pool `take_*` atomicity confirmed — concurrent draws cannot alias an element.
- *Scope reminder:* downstream consumers that route through TruncPr-style opens are statistical by design — the zero-budget claim here covers exactly the §5 operations, nothing above them.

## 6. Status and conditions for the KLR lift

**Status: adversarially verified (five independent refutation attempts); outcomes folded in.** Surfaces 1 (degree-2t safety vs. actual decode code), 3 (chain joint uniformity incl. cross-reveals), and 4 (RandBit sampling vs. the code's actual Tonelli–Shanks root) **held**. Surface 5 forced the Type-A condition's correction from per-open single-use to per-protocol joint simulatability (now in §3), plus the Type C class for $r^2$ and the Beaver caller-discipline assumption. Surface 2 found the one substantive issue: **"zero simulation error" is conditional on fixing the zero-share verifier's exact-degree test** (`zero_share.rs:514`, accept $\le 2t$ instead of == 2t) — without the fix the perfect core is perfect-minus-$\Theta(t/q)$, which fails KLR Thm 1.2's *perfect* hypothesis on a technicality (and Thm 1.1 says statistical doesn't compose, so the technicality is load-bearing). The fix is a one-line predicate change; the analogous exact-degree checks in `ran_dou_sha`'s verifier go to the provenance track for the same review.

**Conditions for the KLR Thm 1.2 lift, once verified:**

1. Real-to-hybrid: shared with the Masked-Open doc §5d — Open realized by the Tier-1 decoders (this doc's §2 refines what that means per degree), handles committed before first message, pools realized per their own proofs.
2. Tier-1 provenance: the pool-generation protocols (`RanSha`/`RanDouSha`) and decoder correctness rest on DN07/BH08/BGW — the provenance-verification reading plus the sync$\to$async bridging argument. Discharged in the companion doc "Tier-1 Provenance & Sync-Async Bridge": perfect-security provenance rests on AL17 and BTH08 (DN07 is statistical and supplies structure only), and the generation protocols' straight-line simulators are in the Generation Lemma.
3. KLR's own model alignment: security-with-abort (✓ — §2 makes abort explicit), straight-line black-box (✓ by construction), *perfect* (✓, zero error) — plus KLR Cor. 4's secure-channels requirement in the computational deployment (the stoffelnet QUIC check on the engineering list).

With those discharged, every operation in §5 is UC-secure under concurrent composition with no additional argument, and its shared-mode (green) lock classification becomes theorem-backed.
